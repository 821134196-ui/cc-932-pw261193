# 机房搬迁规划台

一个零运行时依赖的机房搬迁规划与断点续跑演示。它把**供电配额、机柜 U 位、链路带宽、数据库副本反亲和/安全副本数**放在同一个约束求解器中，并把用户确认过的步骤写入只追加的真实执行账本。

## 启动

```bash
npm run dev
# 或 npm start
```

默认在未设置 `PORT` 时依次尝试常用本地端口：

- http://localhost:5173
- http://localhost:3000
- http://localhost:8000
- http://localhost:4173

如果设置了 `PORT`（包括 `PORT=0` 随机端口），则只监听该端口。

```bash
PORT=8080 npm start
```

也可以用任意静态服务器打开仓库根目录或 `public/`。此时前端会自动切换到浏览器内置引擎；使用 Node 服务时状态由服务端内存账本维护，并提供 JSON API。

## 验证

```bash
npm test
npm run build
```

测试覆盖：

- 初始计划可求解；
- 31 个步骤可逐条确认到全部完成；
- 容量下调后显示真实账本冲突；
- 中途拔掉 `TP-7` 后保留已完成步骤和已固定上架位置；
- 断电导致供电冲突时，只有上调容量后才能继续；
- 链路带宽冲突会列出共享带宽上的链路组合；
- 临时电源不能重复拔除。

## 推荐演练路径

1. 打开页面，查看初始可行排程和建议机柜/U 位。
2. 逐条点击步骤右侧的 **“确认执行”**，或点击顶部 **“确认并执行下一条”**。
3. 点击 **“载入中途断点”**：系统会确认订单库/账务库主节点的副本、下线、上架，并给订单库主节点上电，然后拔掉临时电源 `TP-7`。
4. 右侧会出现 `PDU-A` 的供电冲突组合：已上架的 `order-db-01 + ledger-db-01` 合计 `4.8 kW`，超过拔除临时电源后的 `4.2 kW` 配额。
5. 在左侧把 `PDU-A · A 列头柜` 供电容量调整到 `4.8` 以上（例如 `6 kW`）。求解器会从当前执行点重算，未上架机器可改派机柜，而已上架的两台机器不会被回滚或挪柜。
6. 继续逐条确认直到搬迁完成。

也可以直接点击 **“拔掉临时电源 TP-7”**。如果当时尚未把多台高功率机器固定到 `PDU-A`，求解器可能通过改派未上架机器找到新的可行剩余排程；如果已经形成不可逆的固定组合，则显示冲突资源组合。

## 领域模型

- **Power domain / PDU**：供电容量（kW），临时电源 `TP-7` 为 `PDU-A` 提供 `2.8 kW`。
- **Rack**：U 位容量、所属 PDU；上架步骤会选择机柜和连续 U 位。
- **Link pool / Link**：多条链路共享带宽池，链路步骤要求双端已上电。
- **Replica set**：数据库副本安全下限和机架反亲和；主节点下线前必须完成副本同步检查点。
- **Execution ledger**：已确认步骤、实际上架位置、已上电机器、已开通链路和事件账本。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 获取状态、资源用量、冲突和装饰后的步骤 |
| `POST` | `/api/reset` | 重置；请求体 `{"scenario":"midway"}` 可直接进入中途断电场景 |
| `POST` | `/api/demo/midway` | 进入内置中途断点并拔除临时电源 |
| `PATCH` | `/api/capacities` | 修改容量，例如 `{"kind":"power","resourceId":"pdu-a","value":6}` |
| `POST` | `/api/steps/:id/confirm` | 确认一条步骤并推进真实执行点 |
| `POST` | `/api/power/unplug-temp` | 拔除临时电源 |
| `GET` | `/api/health` | 健康检查 |

容量类型 `kind` 支持：`power`、`rackUnits`、`linkBandwidth`、`replicaMin`。

## 设计说明

求解器会枚举未上架机器的候选机柜，检查连续 U 位、供电峰值、共享链路带宽、副本数量和机架反亲和。不可行时，除了给出当前容量下的最佳冲突见证，还会通过删除法寻找最小不可排程机器核心；每张冲突卡列出具体机器/链路组合、需求量、容量缺口和处理建议。

已确认的下线、上架、上电、业务恢复等动作被视为执行点。重新求解只决定**尚未确认**的步骤和**尚未固定**的位置，不提供自动回滚。“重置演练”仅用于重新开始演示。
